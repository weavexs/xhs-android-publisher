# 快速发布路径 v2（隔离 alpha）

## 为什么不是让模型每一步都操作

System One 是文本分类/结构化决策服务，不是手机截图模型。
本地代码掌握账号、授权、内容版本和副作用，模型只回答边界清晰的小问题。
已知控件直接定位；只有普通导航控件发生变化，才提交脱敏候选列表。
正常路径可以是零模型调用。这是减少延迟，而不是强行增加模型参与。

参考（2026-09-22 查阅；未复制第三方实现）：

- [官方构建指南](https://docs.typesafe.ai/concepts/how-to-build-with-system-one)：确定性代码负责流程与副作用，模型负责原子判断。
- [官方 Python SDK](https://github.com/typesafe-ai/typesafe-sdk-python)：有界调用、显式重试配置；本实现用标准库，不增加 SDK 依赖，默认零重试，不记录请求/响应正文。
- [官方 adapter](https://github.com/typesafe-ai/system-one-adapter-python)：保持决策接口独立，可以基准比较；不自动切换模型来解释不同置信度。
- [社区 playground 的候选提取案例](https://github.com/TypeSafeAI/typesafe-playground/blob/main/docs/document-extraction.md)：先枚举本地真实候选，再选候选 ID。无候选不请求，无匹配与接口失败分开。此仓库不是官方手机发布案例。
- [模型能力与价格](https://docs.typesafe.ai/models)、[接口](https://docs.typesafe.ai/api)：固定 `jev-1.13.0`；当前输入价格 0.042 USD/百万 token，输出免费。上线前应复核价格和能力。

## 精简后的流程

本地校验和授权摘要 → 持久化任务占位 → 唤醒 → 账号页顶核对 → 历史精确标题查重 → 素材一次上传/直接编辑 → 提交前集中复核 → 先持久化 `submitting` 再点发布 → 公开详情验收 → 熄屏复核。

|环节|实现与边界|
|---|---|
|内容绑定|标题、正文、话题及有序图片 SHA 形成摘要；检查逐页来源、文字层、输出图的映射及来源记录。只使用现有素材，不生成/替换图片。|
|账号|同一设备会话核对一次页顶昵称，有效期五分钟；启动、ADB 错误、登录/验证码等异常使会话失效。卡片作者名字不能充当身份。|
|页面读取|0.8 秒快照共享，点击/输入/滑动/应用操作后失效；新 dump 使用唯一临时路径，失败不能读旧 XML。提交前强制刷新。|
|防重复|SQLite WAL + FULL 同步，账号/文章唯一且任务 ID 唯一。占位在唤醒之前；提交标记在点击之前。变更版本、换任务 ID 或重启都不会自动重放。|
|历史查重|新账本中的历史导入仍需检查完整当前/旧标题。模糊关键词已移除。没有确切“没找到我的笔记”结果则停止；不把未找到标题卡片当成不存在。|
|图片|独立相册、手机 SHA、MediaStore 顺序、选中数量、封面第一和选中顺序截图。提交前还核对编辑页可见张数；设备无法展示全部张数时停止，不猜。|
|正文/话题|继承已验证的中文粘贴与原生话题解析提示校验；正文精确匹配。当前话题证据是最后一个标签的原生解析提示及完整正文，不声称逐一打开所有话题。|
|结果|必须有主页卡片、完整标题/正文、公开可见和详情截图哈希；上传完成或返回主页都不算发布成功。|
|熄屏|发送熄屏后读取 display 与 power，间隔后再次确认。公开已成功但熄屏失败，记录清理告警，不能重发。|

## TypeSafe 限制

- 默认禁用；设置 `TYPESAFE_API_KEY` 并显式传 `--allow-typesafe-text` 才启用。密钥只从环境读取；不要把密钥写进命令行、日志或 Git。
- 仅上传固定白名单中的普通导航文字和临时候选 ID。没有截图、坐标、正文、标题、账号名、私信或资源 ID。
- 一次请求批量问页面分类及目标候选；页面分类只是诊断，不能授权任何动作。
- 目标候选检查完整概率分布、选中概率 ≥ 0.95、confidence ≥ 0.9。高置信度也不等于事实正确，还要本地验证目标类别以及请求前后的页面指纹。
- 每次工作流最多两次请求、单次五秒超时、零自动重试。按每次最多 64k 输入 token 预留费用；失败保留预留，防止重复计费。
- 不允许模型定位最终发布、预约、删除、登录、支付、验证码、隐私或安全设置操作；这些路径不进入 router。

## 使用

在仓库根目录运行。配置文件继续遵循 `assets/xhs_config.example.json`，使用已验证的本地 USB 配置。所有设备操作必须独占该手机，不能与旧调度或人工操作同时进行。

```bash
# 仅本地校验，打印待人工确认的内容摘要，不操作手机
python3 -m agent.publish preflight ARTICLE_ID --config /path/to/private-config.json

# 只读真机探测：唤醒、核对账号、检查同页缓存、熄屏；不进入编辑器
python3 -m agent.publish probe --config /path/to/private-config.json

# 仅在明确批准对应文章和精确版本后运行；不要自动填入摘要
python3 -m agent.publish publish ARTICLE_ID --config /path/to/private-config.json \
  --task-id UNIQUE_APPROVED_TASK --approve-digest USER_APPROVED_DIGEST
```

默认状态目录 `~/.local/share/xhs-phone-agent/publish-v2`，SQLite 与回执应一起备份。
不要通过删除账本、换状态目录或换账号名字绕过重复保护。账号当前以配置的名字为账本命名空间，正式接入时应改为服务端不可变账号 ID。
同一用户的新入口共享设备锁，**旧入口不参与该锁**。未完成统一锁/服务端任务接入前，不允许两个发布者并行运行。
失败前未提交也需人工核对后恢复；当前没有自动清空占位或“强制重试”命令。

## 验收和上线边界

- 单元测试：`python3 -m unittest discover -s tests -v`。测试数据全部为合成数据，无真实账号或素材。
- 覆盖重复任务、同文章不同版本、账号隔离、提交断线、账本故障、结果不明、素材错配、模型输出不合法、缓存失效及实际熄屏失败。
- 真机只读探测结果与耗时保存在私有 runtime，不提交截图/设备标识。未进行新的公开发布，不宣称端到端发布耗时已经降低多少。
- 本次 USB 真机 probe 通过：整轮唤醒/账号核对/缓存检查/熄屏 19.6 秒；显式采集同页快照后，三个选择器检查新增 UI 读取为零。整轮 UI 读取仍为三次，不把此局部优化换算成整篇发布提速比例。独立复读 display 确认为 OFF。
- 原有发布入口不变，`python3 -m agent` 仍只连接/心跳，不领取任务。
- 回执是本地 outbox，尚未自动回写服务端。正式接入需统一不可变账号 ID、内容摘要、任务租约和账本，服务端核对证据后确认；不能仅凭 CLI 返回成功更新为已发布。
- 本入口要求原有本地素材映射格式，不代替生产视觉审批、风险审批或字体排版验收。
- 切换前仍需一篇新授权内容进行受控公开验收，确认图片/话题/详情证据和回写；同时停用旧发布调度，防止双调度。不要使用已经发布的文章来测试。
